# pdf2hwpx · 스캔노트

PDF와 이미지의 한글·숫자·표·그림을 읽고, 원본과 편집 화면을 좌우로 비교한 뒤 HWPX 또는 독립 HTML로 저장하는 Windows 프로그램입니다. 저장소 이름은 `pdf2hwpx`, 사용자 화면 이름은 **스캔노트**입니다.

## 사용

검증된 오프라인 배포 폴더의 압축을 모두 푼 뒤 `ScanEdit.exe`를 실행합니다. `install.cmd`는 현재 사용자 폴더에 설치하고 바탕화면 바로가기를 만듭니다. 실행 파일과 `_internal` 폴더를 함께 보관하세요.

1. PDF 또는 이미지를 선택합니다. 긴 PDF는 `4-5,7-8`처럼 변환할 쪽을 지정할 수 있습니다.
2. **내 PC · 오프라인 OCR → 문서 변환**을 누릅니다.
3. 오른쪽 글자와 표 셀을 수정하고 **원본 겹치기**로 위치를 비교합니다.
4. **HWPX 저장** 또는 **HTML 저장**으로 내보냅니다. 그림은 출력 안에 포함됩니다.

HWPX의 일반 글자는 한글의 본문 문단으로 저장합니다. 같은 줄에서 나뉜 글자와 글꼴 조각은 한 문단 안에 묶으며, 실제 표에만 셀이 생깁니다. 그림은 그림 개체로 저장합니다. 본문의 들여쓰기와 줄 간격은 원본 위치를 참고하고, 편집한 긴 문장은 본문에서 줄바꿈할 수 있습니다.

양식의 선·사각 테두리·채움은 편집 가능한 도형으로, 표의 테두리와 셀 채움은 실제 표 서식으로 저장합니다. PDF의 벡터와 스캔의 직선을 추출하며 사진·복잡한 그림은 해당 영역의 그림 개체로 보존합니다. 페이지 전체를 배경 그림으로 깔아 양식을 대신하지 않습니다. 오른쪽에서 선·도형 또는 표 셀을 선택하면 위치·크기·선 색·두께·채움을 바꿀 수 있습니다. 이전 버전의 배경형 편집 자료는 저장할 때 양식 분리를 다시 수행하며, 너무 큰 이전 자료는 새 버전에서 원본을 다시 변환해야 합니다.

한 번에 최대 1 GiB, 500쪽을 받습니다. 한 쪽씩 처리하고 편집 자료를 디스크에 나누어 보관합니다. 큰 이미지는 분할 처리하며 원본 좌표를 유지합니다. 결과는 HWPX 또는 HTML 파일 하나로 저장합니다. 실제 처리 가능 범위와 시간은 입력 복잡도, 가용 메모리와 디스크에 따라 달라집니다.

변환 중 **잠시 멈추기**를 누르면 지금 읽는 부분까지 마치고 완료한 페이지를 보관합니다. 프로그램을 다시 실행한 뒤 **이어서 변환**으로 남은 페이지만 처리할 수 있습니다. 원본이 바뀌거나 저장한 이미지 자료가 사라지면 재개를 거부합니다. 화면은 필요한 페이지만 불러오며 저장하지 않은 수정이 있는 상태에서 문서를 바꾸면 확인합니다.

작업 자원 계획은 최대 8 GiB, 운영체제 여유 1 GiB를 기준으로 계산하며 가용 메모리를 알 수 없으면 2 GiB의 보수적 기준을 사용합니다. 소형 AI는 계산된 자원에 맞을 때만 실행합니다. 모든 입력의 프로세스 메모리 상한을 보증하는 수치는 아닙니다.

현재 앱과 소유한 자식의 메모리도 예산에 포함하고, 변환·AI 시작·내보내기를 함께 실행하지 않습니다. 이미지 디코더와 AI 자식에는 별도 commit 제한을 적용합니다. 부모 프로세스는 측정과 다음 작업 입장 제어를 사용하며 브라우저 메모리는 별도입니다.

## 인식 방식과 자료 보관

| 방식 | 조건 | 처리 |
|---|---|---|
| 내 PC OCR | 준비된 한국어 ONNX 모델 | CPU·오프라인. PDF 원본 글자 층이 있으면 직접 추출 |
| 내 PC 소형 AI | 별도 Qwen3-VL 2B와 llama.cpp 런타임 | OCR 배치를 유지하며 어려운 글자 최대 2줄 검수 |
| OpenAI / Gemini | 사용자 API 키와 인터넷 | 선택한 제공자에 페이지 이미지를 전송 |
| Ollama | 실행 중인 비전 모델 서버 | 지정한 로컬 서버 사용 |

내 PC 방식은 문서를 외부 서비스에 전송하지 않습니다. API 키는 현재 화면과 요청 메모리에서 사용하며 문서 편집 JSON에 저장하지 않습니다. 연결 확인은 서버·모델 조회이고 실제 인식 성공을 의미하지 않습니다.

**편집 내용 저장**은 JSON으로 수정 상태를 보관합니다. 다시 열려면 같은 PC의 작업 폴더에 원본 이미지 자료가 남아 있어야 합니다. 종료 후에도 로컬 `data`에 자료가 남을 수 있으므로 필요에 맞게 관리하세요.

## 품질과 한계

95%는 개발 목표입니다. 독립 정답과 비교한 CER과 WER로 평가하며 인식 신뢰도를 글자 정확도로 간주하지 않습니다. 제한된 2,811개 원본 글자의 위치 대응 평가에서 화면 이미지 CER 3.9488%, PDF 150 DPI 이미지 CER 4.0555%를 확인했습니다. 모든 페이지가 목표를 넘지는 않았고, 그림 내부의 정답이 없는 글자는 평가하지 않았습니다. 범위와 한계는 [공개 검증 기록](docs/VALIDATION_PUBLIC.md)을 확인하세요.

원래 글꼴·자간·색상·복잡한 도형, 무테 표, 손글씨와 크게 기울어진 사진을 완전히 복원하지 못할 수 있습니다. 숫자·금액·날짜와 중요한 문서는 원본을 대조하세요. NPU 가속과 상용 API 실결제 변환은 검증하지 않았습니다. 합성 예제는 실제 문서 정확도의 근거가 아닙니다.

## 개발

Python 3.12 x64 / Windows 기준:

```powershell
python -m venv .venv
.venv/Scripts/python -m pip install -r requirements.txt
.venv/Scripts/python scripts/prepare_models.py
.venv/Scripts/python -m converter.demo
.venv/Scripts/python app.py
.venv/Scripts/python -m unittest discover -s tests -v
```

소형 AI를 개발·패키징하려면 `scripts/prepare_sllm.py`를 별도로 실행합니다. 모델 준비에는 인터넷과 다운로드 공간이 필요합니다. 실행 단계에는 자동 모델 다운로드가 없습니다. 소형 AI 모델은 공개 소스에 포함하지 않습니다. 버전·출처·SHA256은 준비 스크립트와 생성된 manifest에 기록됩니다.

`python scripts/build_windows.py`는 Windows 폴더형 배포물을 만듭니다. 빌드 PC의 C++ 런타임 준비와 각 구성요소의 재배포 조건을 먼저 확인하세요. 실행 파일은 최종 소스에서 다시 만들고 패키지 시험을 통과한 뒤 배포해야 합니다. 공개 CI는 모델을 별도로 다운로드하지 않으며 모델·비공개 원본이 필요한 시험은 생략을 표시합니다.

공개 전에 `python scripts/public_source.py`와 `python scripts/public_source.py --check-index`를 실행합니다. 입력 문서, 스크린샷, 결과물, API 키와 비공개 협업 자료는 커밋하지 않습니다. [공개 절차](docs/GITHUB_RELEASE.md), [기여 안내](CONTRIBUTING.md), [보안 제보](SECURITY.md)를 참고하세요.
